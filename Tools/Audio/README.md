# Tools/Audio: synthesised sound for Andrew's Airsoft

Every sound effect, ambience and music loop in the game is generated by code.
There are no recorded or downloaded samples. `make_sounds.py` (Python 3 + numpy) writes
**48 kHz / 16-bit PCM WAVs** to `Tools/Audio/Generated/<Key>.wav`. The Unreal editor
setup script (`Content/Python/airsoft_setup.py`) imports every `Generated/*.wav`
to `/Game/Airsoft/Audio/<Key>`. Gameplay code then loads them by key through
`AirsoftAssets::Sound(Key)` / `Play2D` / `Play3D`.

The audio direction is a neo-noir, big-screen action mood. Gunfire is **cinematic** by
default, and the original mechanical **airsoft** gun sounds are kept as an alternative set.
All music, motifs, riffs and sound design are original. They aim at a genre (brooding
neo-noir, dark industrial techno, lounge noir, action-movie gunfire), not at any existing
film score, song or sound design.

## Regenerate

```bash
python3 Tools/Audio/make_sounds.py                      # everything: Generated/ + _overview.png
python3 Tools/Audio/make_sounds.py FireRifle MagIn      # just these keys
python3 Tools/Audio/make_sounds.py --only FireRifle,SteelDing
python3 Tools/Audio/make_sounds.py --list               # keys, group, channels, loop flag, variation count
python3 Tools/Audio/make_sounds.py --jobs 1             # single process (default: up to 4 workers)
```

* **Requirements:** numpy. Optional: scipy (if importable, `scipy.signal.sosfilt` does the
  IIR filtering; otherwise filters run as exact frequency-domain IIR responses, which
  give the same output to ~1e-11). Pillow is used for the `_overview.png` contact sheet.
* **Deterministic:** every key/variation seeds its own RNG from `crc32("<Key>#<var>")`.
  Re-running reproduces byte-identical files, and rebuilding one key never changes another.
  The renamed airsoft keys keep the seed of their old name (recipe option `seed`), so
  `FireRifle_Airsoft*.wav` are byte-identical to the files previously written as `FireRifle*.wav`.
* **Re-runnable:** files are overwritten in place. A full run also deletes stale
  `*.wav` files that no longer belong to any key.
* **Run time:** about 1-1.7 minutes for the full set with 4 workers on a 4-core machine
  (the critical path is ClubMusic, 45-75 s depending on load, with MenuMusic and the ambiences
  running beside it). One-shots take well under a second each.
* At the end the script prints a check table for every file: peak, true peak, RMS,
  loudest 50 ms RMS, integrated loudness (BS.1770 LUFS), onset time, spectral centroid, DC,
  clipped-sample count and the loop seam metric. It also writes `Generated/_overview.png`,
  a waveform + log-frequency spectrogram contact sheet of every one-shot and loop.

## Output conventions

| | |
|---|---|
| Format | 48 kHz, 16-bit PCM WAV, TPDF-dithered |
| Channels | **mono** for positional (3D) one-shots; **stereo** for 2D UI / feedback / stingers, ambience and music |
| Level | one-shots and ambiences normalised to **-1 dBTP** (4x-oversampled true peak), so nothing clips. Music loops are mastered to an **integrated-loudness target** (see below), never above -1 dBTP |
| One-shots | 20 Hz DC/rumble high-pass + gentle 17.5 kHz air low-pass, leading silence trimmed to the transient, trailing silence trimmed below -62 dB, 5 ms raised-cosine fade-out |
| Loops | seamless by construction (see below); circular 20 Hz high-pass + 17.5 kHz low-pass, zero DC |
| Variations | `<Key>_01.wav`, `<Key>_02.wav`, ... **plus** `<Key>.wav` (a copy of `_01`), so the plain key always exists |

### Loops

The ten loops are marked **LOOP** in the tables below.

* **Ambiences** are synthesised circularly. Noise beds are coloured in the FFT
  domain, so they are periodic. Slow gust/swell modulators come from periodic random
  spectra. Filters and reverbs run as circular convolutions. Any event (bird call,
  car pass, distant burst) that runs past the end wraps around to the start. The loop
  point is therefore mathematically continuous, with no crossfade dip.
* **Music** is rendered once with all reverb and delay tails, then everything past
  the loop end is overlap-added back onto the start (`dsp.fold_tail`, the
  standard "wrap the tail" crossfade). Continuous layers (the menu drone, the staging
  brush swirl) are built circularly at exactly the loop length with loop-periodic
  frequencies and added after the fold.
* **Music loudness:** `finish_loop(..., lufs=...)` sets the integrated loudness (BS.1770-4,
  K-weighted, gated) to the target. If that would push the true peak over -1 dBTP, a
  circular look-ahead limiter (`dsp.limit`) catches the peaks, so the seam stays
  continuous. Targets: ClubMusic -16, MenuMusic -18, PostRoundMusic -19, StagingMusic -21 LUFS
  (deliberately quieter).
* **SlowMoHeartbeat** is a 2 s loop built circularly (circular mix, reverb, filters).
* The check table's `seam` column is |last sample - first sample| divided by the
  file's 99.9th-percentile sample-to-sample step. Values below 1 mean the seam is an
  ordinary step. All loops measure 0.01-0.42.

## How Unreal imports them

`Content/Python/airsoft_setup.py` (the editor setup script) imports every
`Tools/Audio/Generated/*.wav` as a SoundWave named after the file, under
`/Game/Airsoft/Audio/<Key>`. That content folder is git-ignored and regenerated.
Code resolves `/Game/Airsoft/Audio/<Key>.<Key>`:

* `AirsoftAssets::Play3D(this, "FireRifle", Location, ...)` is positional, with the
  project's airsoft attenuation. Use the mono files.
* `AirsoftAssets::Play2D(this, "UIClick", ...)` is non-spatial. Use the stereo files.

Notes for the import script / audio setup:

* Looping on import: `airsoft_setup_lib/importers.py` sets `looping = True` for keys in
  `LOOPING_KEYS`, plus any key starting with `Ambience` or ending in `Music`. The new
  `PostRoundMusic` and `StagingMusic` are covered by the `...Music` rule, so they loop
  without any importer change.
* `SlowMoHeartbeat` is loop-ready (seamless) but is **not** flagged looping on import, and it
  should stay that way while the replay plays it with fire-and-forget `Play2D` (a looping
  wave started that way would never stop). To loop it under a longer bullet-time, play it
  from an `UAudioComponent` with looping on and stop it when the replay ends.
* `_overview.png` is not imported (only `*.wav` is).
* Code plays the plain `<Key>`. That is the first variation, and it already gets per-shot
  pitch randomisation in code. To use every variation, wrap `<Key>_01..N` in a SoundCue
  Random node, or pick `"%s_%02d"` at random in code. This matters most for automatic
  fire: the four cinematic variations differ in micro-timing, tone and tail.

### Choosing the gunfire set

Weapons name their sound through `FAirsoftWeaponData::Sound` (e.g. `TEXT("FireRifle")`), and
`GunSoundKey()` in `AirsoftCombatComponent.cpp` picks the file per listener:

* **Cinematic (default):** `FireRifle`, `FireSMG`, ... (no suffix).
* **Airsoft:** with the settings option *Gun sounds = AIRSOFT* (`bCinematicGunSounds` off) the
  game plays `<Key>_Airsoft`.
* **Distant:** in cinematic mode, remote shots beyond `FarGunfireDistance` (40 m) play
  `<Key>_Far`. The files already contain the distance filtering, the crack-before-boom gap
  and the late tail, so give them gentle distance attenuation.
* `FireSniper` is only used by the VSR-10, which is integrally suppressed ("whisper-quiet" in
  `AirsoftWeaponData.cpp`), so its cinematic voice is a heavy suppressed thwump followed by the
  bolt cycle rather than an open-muzzle boom.

Other cues the code already uses: `PostRoundMusic` (2D under the after-action report, faded
in and out; it loops via the `...Music` import rule), `StagingMusic` (an in-world speaker in
the staging layout), and `ReplayWhoosh` / `SlowMoHeartbeat` / `ReplayImpact` in the kill replay
(the replay also plays `FireRifle` at pitch 0.55 for the slow-motion shot).

### Suggested starting volumes

Loops: AmbienceField / Street / Interior / Staging are about -23 (Staging) to -15 (Interior,
dense crowd) LUFS (use about 0.6-1.0). ClubMusic is -16 LUFS (use about 0.35-0.5 under
gameplay; it also comes from in-world speakers). MenuMusic is -18 LUFS (about 0.7).
PostRoundMusic is -19 LUFS (about 0.7-0.8). StagingMusic is -21 LUFS (about 0.8-1.0;
it is quiet on purpose). Cinematic gunfire is peak-normalised like the airsoft set, with similar loudest-50 ms
levels but much longer tails. The `_Far` files are dense (mostly tail, -11 to -16 LUFS) and
should sit well below the close shots.

## How the recipes work

### Cinematic gunfire (`cinematic.py`)

A movie gunshot is designed, not recorded as one event. Each shot is built from layers
whose parameters differ per weapon class (`WEAPONS` table):

* **Crack:** a supersonic N-wave (instant rise, linear fall, instant return; 0.2-0.55 ms
  long, which puts its energy at ~2-8 kHz), a band-limited noise snap, an air-rip
  sizzle and a faint muzzle-device ring. Shotgun adds two offset pellet N-waves.
* **Chest thump:** a sine body that drops from 95-170 Hz to 38-75 Hz with a 10-30 ms time
  constant, plus a short octave partial so it reads on small speakers, saturated and low-passed.
* **Body + bark:** a 130-330 Hz low-mid burst and a noise burst through three or four
  formant resonances, with a falling tone, driven into saturation (the midrange punch).
* **Mechanism** (`mech.py`), slightly behind the blast: bolt carrier / slide clacks (inharmonic
  steel modes + strike click + mass thump), buffer-spring zing, friction, belt-link rattle,
  pump stroke, bolt cycle.
* **Environment:** two or three slap echoes (each low-passed and blurred), a synthesised
  0.5-1.3 s T60 reverb with early reflections (lows kept out, so the sub stays in the short
  thump), and for DMR / LMG / Magnum / Shotgun a "rolling" tail of darker,
  blurrier reflection clusters at growing gaps.
* **Glue:** boom + mechanism + tail form one bus that is saturated and run through a
  look-ahead limiter (4.5-7.5 dB on its peaks) for density. The crack is laid on top
  afterwards, untouched, so it stays the sharpest and highest peak.
* **Variations** change mechanism micro-timing (up to +-10 %), crack length (+-15 %), every pitch
  (+-4 %), formant placement, slap times (+-12 %), reverb length and all noise/IR seeds.
* **Distant versions** reuse the blast layers. The crack is first, rounded and low-passed.
  The boom comes after a weapon-specific delay through a 4th-order low-pass. Then a 1.6 s
  field tail, late slaps and rolling.

### Airsoft gunfire (`weapons.py`, the alternative set)

Airsoft guns do **not** go bang. Each airsoft recipe layers the real mechanical events,
glues them through a little oversampled tanh saturation, and adds a short outdoor tail:
AEG piston slap + receiver ring + air puff + BB snap + gearbox whir and latch ticks;
gas-blowback crack + gas jet + slide clacks; shotgun whump + BB hiss; spring-bolt
thunk + cylinder ring + mainspring twang.

### Adding or changing a sound

Add an entry to the `RECIPES` dict of the relevant module:
`"Key": (fn, variations, "description"[, {"ch": 2, "loop": True, "lufs": -18.0, "seed": "OldKey"}])`.
Here `fn(rng, var)` returns a float array: `(n,)` for mono, `(2, n)` for stereo. The driver
handles seeding, finishing (trim / fade / normalise, or loop high-pass + loudness), writing
the variation files, the check table and the contact sheet. Run `make_sounds.py Key` while
iterating. To retune a gun, edit its row in `cinematic.WEAPONS`.

## Size

The full set is **165 files, about 121 MB** (decimal). That is slightly over the ~120 MB
target. Almost all of it is the ten stereo loops at their stated lengths:
4 x 60 s ambience (46.1 MB), ClubMusic 120 s (23.0 MB), MenuMusic 90 s (17.3 MB),
StagingMusic 75 s (14.4 MB), PostRoundMusic 40 s (7.7 MB), SlowMoHeartbeat 2 s (0.4 MB).
48 kHz / 16-bit stereo is 11.5 MB per minute, so the loops alone are about 109 MB. The
155 one-shot files are about 12 MB (cinematic gunfire 3.6, distant 2.2, airsoft 1.5). Ways
to get well under: shorten the ambiences to 30-40 s or write them at 32 kHz, or keep
`Generated/` out of git and regenerate it (as is already done for `Content/Airsoft/Audio/`).
Unreal compresses on import either way, so the shipped size is much smaller.
